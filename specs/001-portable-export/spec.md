# 素材ごとのポータブル書き出し(Windows)

> spec.md — フィーチャーの「何を・なぜ」。正本はこのテキストと GitHub(Feature issue)。

## 目的
OBS の「ツール」メニューから、いま開いているシーンコレクションを**素材ファイルごと 1 つのフォルダへ書き出し**、
別の PC で**プラグインを入れていない素の OBS**の「シーンコレクション → インポート」だけで、不足ファイル無しに開けるようにする。

## 背景 / 課題
- OBS 標準の「シーンコレクション → エクスポート」は JSON しか書き出さない。素材は元 PC の絶対パスを指したままなので、別 PC では全部「見つからない」になる。
- 既成プラグイン Scene Collection Manager の Export は素材も集めるが、パスを `./` 無し(`sources/<ソース名>/settings/file/xxx.png`)で書くため、受け取り側にも同プラグインが要る。
- OBS 標準インポート(obs-studio `frontend/importers/studio.cpp` の `TranslatePaths`)は、**`./` で始まる文字列だけ**を「読み込んだ JSON のフォルダ基準」の絶対パスに直す。したがって参照を `./assets/...` で書けば、受け取り側は何も入れずに開ける。
- 同じ変換は作者が手元の CLI で運用しており、実運用で問題なく開けている。これを OBS の中から 1 操作でできるようにする。

## スコープ
- **含む**:
  - OBS の「ツール」メニューに項目「ポータブル書き出し…」を足し、ダイアログで出力先の親フォルダと「zip も作る」を選んで書き出す
  - 出力 = `<親フォルダ>/<コレクション名>/` に `<コレクション名>.json` と `assets/`。「zip も作る」を選んだら、出力フォルダと同じ名前の `<親フォルダ>/<出力フォルダ名>.zip` も作る
  - 書き換え対象: ソース・グループ・トランジション・フィルタ・シーンアイテムの表示/非表示トランジションの設定のうち、OBS が素材ファイルとして扱うキー
    (`file` / `local_file` / `path` / `image_path` / `track_matte_path` / `text_file`)と、スライドショー `files[].value`・VLC ビデオソース `playlist[].value`
  - 書き出し前に OBS に保存させ、未保存の変更も含めて書き出す
  - 同名で別ファイルは `_2` `_3` … の連番、同じファイルの複数参照は 1 コピーを共有
  - 見つからない素材は元のパスのまま残し、書き出し後に一覧で知らせる
  - 日本語を含むソース名・ファイル名・フォルダ名
  - 対応 OS は Windows(x64)。OBS 31 系
- **含まない**:
  - macOS / Linux 版(変換部分は OS 非依存に作るが、配布・動作確認は Windows のみ)
  - 上に挙げたキー以外でファイルを指す設定(サードパーティ製プラグインのソース・フィルタ独自のキーなど)
  - ブラウザソースのローカル HTML が相対参照している周辺ファイル(HTML 本体だけコピーする)
  - スライドショーの「フォルダ指定」の展開(`files[].value` がフォルダのときは 1 ファイル扱いにせず欠落として一覧に出す)
  - 書き出したものを読み込む側の機能(読み込みは OBS 標準のインポートを使う)
  - GitHub Release での配布・README の使い方(別タスク)

## 受け入れ条件
- [ ] 「ツール」メニューに「ポータブル書き出し…」が出て、選ぶとダイアログが開く
- [ ] 書き出すと `<親フォルダ>/<コレクション名>/<コレクション名>.json` と `assets/` ができ、JSON 内の対象キーの値は全て `./assets/<ファイル名>` になっている(見つからなかった素材を除く)
- [ ] `assets/` のファイルは元ファイルとバイト単位で一致する
- [ ] 同名で別内容の素材は `_2` などの連番で両方残り、同じファイルを複数のソースが参照しているときは同じファイル名を指す
- [ ] 見つからない素材があっても書き出しは最後まで進み、終了時のダイアログに「ソース名 / 元のパス」の一覧が出る
- [ ] 「zip も作る」を選ぶと `<出力フォルダ名>.zip` ができ、展開すると出力フォルダと同じ中身(JSON と `assets/`)になる。日本語のファイル名が化けない
- [ ] 同名の出力フォルダ(または同名の zip)が既にあるときは上書きせず、`<コレクション名>_2` のように別名で書き出す
- [ ] 書き出し中も OBS の画面は固まらない(進捗ダイアログが出る)
- [ ] 保存操作をしていない直前の変更も書き出しに入っている
- [ ] 別の Windows PC の、このプラグインを入れていない OBS で書き出した JSON をインポートすると、元 PC と同じ見た目で開ける。不足ファイルのダイアログは、書き出し時の欠落一覧に出た素材がある場合だけ、その素材についてだけ出る

## メモ / 降りる箇所
- メニュー・進捗ダイアログ・未保存の変更・別 PC の素の OBS で開けるか、は人が実機で確かめる(tasks.md の H1。手順は plan.md「リスク / 降りる箇所」)。
- 変換部分(`core/`)は OBS にも Qt にも依存しない C++ ライブラリにし、ヘッドレスでテストする。OBS に繋ぐ部分(`src/`)はビルドが通ることを GitHub Actions で確かめ、動作は H1 で見る。
